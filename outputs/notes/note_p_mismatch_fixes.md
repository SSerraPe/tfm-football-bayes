# P-mismatch Fixes — Session 8/9 Audit

Generated by Block G (Session 9, 2026-07-02).

## Problem description

After the Session 8 rebuild (P: 53→48, GK exclusion, transforms), several post-processing
scripts produced errors or silently incorrect output because they constructed tibbles where:
- One dimension came from `feature_names` (P=48 post-rebuild)
- Another came from a pre-rebuild model summary (P=53): the stage-09 simulation fit
  (never rerun with P=48) or the stage-03 diagonal fit (run in May 2026 on old data)

The errors manifest as "Tibble columns must have compatible sizes: Size 48 vs Size 53".

---

## Three runtime fixes applied (Session 8, July 2026)

### Fix 1 — Stage 11: `make_variance_decomp()` feature column

**File:** `scripts/11_loading_analysis_and_chains.R:124`

**Bug:** `tibble(feature = feature_names, sigma_a_diag_mean = sa$mean, ...)`
— `feature_names` has 48 elements but `sa$mean` has 53 elements (from stage-09 sim summary).

**Fix:** `tibble(feature = sa$observed_variable, ...)`
— `sa$observed_variable` returns the row names from the summary object itself,
so row count always matches the summary data regardless of `feature_names`.

**When triggered:** Stage 11 processes both stage-10 (P=48) and stage-09 (P=53) model summaries
in a single run. The sim summary still has P=53 until stage-09 is rerun with rebuilt data.

---

### Fix 2 — Stage 13: truth recovery guard

**File:** `scripts/13_pca_postprocessing.R:315`

**Bug:** `if (!is.null(truth_Lambda)) { cor(L_pca_true[, q], L_pca_mean[, q]) ... }`
— `truth_Lambda` loaded from stage-09 fit has 53 rows; `L_pca_mean` from stage-10 has 48 rows.
`cor()` fails with "incompatible dimensions".

**Fix:** `if (!is.null(truth_Lambda) && nrow(truth_Lambda) == nrow(L_pca_mean)) { ... }`
— Skips the recovery comparison when dimensions don't match. No data is lost; the comparison
section simply doesn't run until stage-09 is rerun with rebuilt data.

---

### Fix 3 — Stage 16: diagonal vs low-rank ICC comparison guard

**File:** `scripts/16_icc_analysis.R:161`

**Bug:** `tibble(feature = feature_names, icc_player_diag = diag_pa$mean, ...)`
— `feature_names` has 48 elements; `diag_pa$mean` has 53 elements from the old stage-03
diagonal posterior summary (fitted on N=4944, P=53 data in May 2026).

**Fix:** `if (!is.null(diag_pa) && !is.null(diag_pb) && nrow(diag_pa) == length(feature_names)) { ... }`
— Skips the comparison figure when P doesn't match. The comparison becomes available once
stage-03 is refit on rebuilt data (Block D, Session 9).

## Dynamically safe patterns (no hardcoded P)

Most pipeline scripts read P from the model at runtime:
- `feature_names <- model_objects$variable_names; P <- length(feature_names)` — stages 11, 14, 16, 19, 20, 22
- `K <- stan_data$Q_a` — `src/stan_helpers.R`
- `I <- length(model_objects$player_levels)` — `src/simulation_helpers.R`
- `sa$observed_variable` (not `feature_names`) — `make_variance_decomp()` in stage 11 after Fix 1

---

## Root cause

When stage-09 (P=53 simulation) and stage-03 (old diagonal baseline, P=53) persist alongside
the rebuilt production fits (P=48), any script that loads summaries for BOTH and mixes them
with `feature_names` will hit the mismatch. The three guards above handle this gracefully.

Permanent resolution requires running stage-09 with P=48 (sim uses `SIM_P` hardcoded to 10,
independent of the real data P — not applicable) and stage-03 with the rebuilt data (Block D,
Session 9, which regenerates `03_real_diagonal_additive_posterior_summary.csv` with P=48).

After Block D, Fix 3 (stage-16 guard) will activate the ICC comparison plots automatically
without any further code changes.
